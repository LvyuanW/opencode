# 剧本复刻技能

## 技能定位

这是一个**实操型创作技能**，不是只会讲原则的分析器，也不是默认一口气写完整季的一键出稿器。

它的目标是：

1. 先把参考材料整理成可分析输入
2. 再把原剧真正有效的机制拆出来
3. 再把机制迁移成新剧方案
4. 再逐步落成角色、目录、分集和自检文档

输出时既要能继续推进，也要给用户留下明确的把控点。

---

## 默认工作方式

默认按以下方式工作：

- **首次触发时，默认先创建或更新 `00_任务卡.md`**
- **每一步先读取对应 reference，再输出结果**
- **每一步都优先落成 md 文档**
- **聊天窗口只展示摘要，不把整份文档原样刷屏**
- **每完成一步，都提示用户下一步可执行指令**
- **所有产物都必须写入当前工作空间根目录，不得写入 skill 目录、`.skills/` 目录或 `references/` 目录**
- **`references/` 只用于读取方法，不用于保存产物**
- **只要宿主环境支持写文件，就必须真实落盘，不能退化成“仅在对话里组织输出”**
- **如果用户明确说“继续”“按默认流程往下走”“直接整套跑”**，可以连续执行多个阶段  
  但仍然要按阶段落成对应 md 文件，而不是跳过中间过程

## 核心原则

### 1. 复刻的是机制，不是表层

优先保留：

- 节奏
- 爽点触发时机
- 角色功能关系
- 单集推进方式
- 结尾钩子逻辑

优先替换：

- 角色身份外壳
- 事件表层
- 场景壳
- 关系表层
- 台词表达

### 2. 先产文档，再推进下一步

不是先在对话里长篇输出，再说“建议保存成文件”。

而是：

1. 明确当前阶段
2. 生成对应 md
3. 聊天中给摘要
4. 引导下一步

对首次触发尤其如此：

1. 先落 `00_任务卡.md`
2. 再决定是否继续执行后续阶段
3. 不能把“任务卡”省掉直接进入纯聊天分析

### 3. 允许连续推进，但不能失控推进

如果用户要高效率推进，可以连续执行：
`参考整理 → 风格拆解 → 复刻方案 → 角色映射 → 目录`

但在以下节点必须显式提醒用户注意：

- 准备扩展完整目录时
- 准备批量写分集时
- 准备导出最终稿时

### 4. 材料不足时，不装懂

必须明确区分：

- 已知
- 可推断
- 无法确认
- 需要补充

## 工作流

```text
开始
→ 参考整理
→ 风格拆解
→ 复刻方案
→ 角色映射
→ 目录
→ 分集
→ 自检
→ 导出
```

这是默认主链路。  
若用户只想做其中一步，也可以单独执行。

说明：

- 以上名称是**阶段名**，不是必须依赖 slash command 的命令
- 在 writer 模式下，用户说“开始”“先做风格拆解”“继续到目录”“先给我样章”“做一下自检”都应视为对应阶段触发
- 若用户只是自然语言描述“我想复刻这个剧本并先出目录”，也应自动匹配到对应阶段，不要求用户输入 `/开始`
- 若用户第一次触发这个 skill 且没有明确禁止建档，默认先建立 `00_任务卡.md`

## 分阶段执行要求

## 1. 开始阶段

作用：建立任务，不急着直接写剧本。

首次触发规则：

- 只要用户第一次触发本技能，默认立即执行本阶段
- 即使用户一上来就说“先出目录”“先拆风格”“先写样章”，也要先创建或更新 `00_任务卡.md`
- 如果信息足够，可以在写完 `00_任务卡.md` 后继续执行用户指定阶段
- 如果信息不足，也必须先把已知信息、缺失信息和建议路径写进 `00_任务卡.md`

必须确认：

- 用户给的是完整剧本、目录、片段、梗概，还是混合材料
- 本次目标是：只分析 / 试做 / 完整开发 / 降低相似度重做
- 目标体量：样章 / 10集内 / 30-40集 / 50-70集
- 目标风格：更像原作 / 中等迁移 / 低相似度迁移

输出：

- `00_任务卡.md`

聊天中只显示：

- 任务目标
- 已接收材料
- 已生成文件：`00_任务卡.md`
- 推荐下一步：`参考整理`

`00_任务卡.md` 至少包含：

- 当前项目目标
- 已接收材料清单
- 当前阶段判断
- 已知 / 可推断 / 缺失信息
- 推荐工作路径
- 是否适合直接继续下一个阶段

---

## 2. 参考整理阶段

执行要求：

- 读取 `references/source-analysis.md`
- 把材料类型、已知信息、缺失信息、可分析范围整理清楚
- 不在这一步直接做长篇创作

输出：

- `01_参考材料整理.md`

聊天中要给：

- 已知什么
- 还缺什么
- 现在适合进入 `风格拆解` 还是先补材料

---

## 3. 风格拆解阶段

执行要求：

- 读取 `references/style-extraction.md`
- 至少分析：题材类型、主角爽点机制、反派压制机制、单集节奏、角色功能关系、台词风格
- 最终总结“可复刻核心”与“不宜直接照搬项”

输出：

- `02_风格拆解报告.md`

聊天中要给：

- 3~6 条最关键结论
- 推荐进入 `复刻方案`

---

## 4. 复刻方案阶段

执行要求：

- 读取 `references/adaptation-strategy.md`
- 必须输出：保留项、替换项、规避项、新剧设定、结构迁移原则
- 当用户没指定相似度目标时，默认走“中等迁移，优先安全”的方案
- 如风险偏高，主动给一个更稳妥的备选方向

输出：

- `03_复刻方案.md`

聊天中要给：

- 当前方案一句话概述
- 3条保留项
- 3条替换项
- 1条主要风险
- 推荐进入 `角色映射`

---

## 5. 角色映射阶段

执行要求：

- 读取 `references/character-mirroring.md`
- 默认先做核心角色，不必一次性扩到所有临时角色
- 每个角色至少写清：原角色、原功能、新角色、新身份外壳、保留功能
- 补充关系迁移与角色弧线简述

输出：

- `04_角色映射档案.md`

聊天中要给：

- 核心角色映射摘要
- 哪个角色最像、最需要再拉开差异
- 推荐进入 `目录`

---

## 6. 目录阶段

执行要求：

- 读取 `references/structure-mapping.md`
- 先按“叙事功能等价”生成目录
- 若用户未指定整季长度，默认先给前 5 集目录样稿
- 只有当用户明确要求时，再扩为完整目录

输出：

- 前 5 集样稿：`05_复刻分集目录.md`
- 完整目录时仍沿用同名文件，按章节补全

聊天中要给：

- 目录的整体节奏判断
- 哪几集承担关键钩子
- 推荐进入 `分集`

---

## 7. 分集阶段

执行要求：

- 读取 `references/scene-recreation.md` 和 `references/script-format.md`
- 默认先写第 1 集样章
- 用户指定具体集数时，按用户要求写
- 保持功能相似、表层不同
- 不直接连续复用参考桥段的外壳与表达

输出：

- 样章：`06_第01集_样章.md`
- 批量写作时：`07_第NN集_标题.md`

聊天中要给：

- 本集承担的叙事功能
- 本集的爽点与钩子
- 推荐进入 `自检` 或继续 `分集`

---

## 8. 自检阶段

执行要求：

- 读取 `references/similarity-checklist.md` 和 `references/compliance-checklist.md`
- 检查两类问题：
  1. 复刻质量是否成立
  2. 相似度与合规风险是否过高
- 必须给出可执行修改建议，而不是只给一句“有风险”

输出：

- `90_复刻质量自检.md`

聊天中要给：

- 优点
- 风险点
- 风险等级
- 下一步建议：重写 / 微调 / 可继续扩写

---

## 9. 导出阶段

作用：

- 整理当前项目已有文档
- 生成一个总索引，方便继续工作或交给别人接手

输出：

- `99_项目索引.md`

索引至少包含：

- 当前已有文件
- 每个文件一句说明
- 当前项目做到哪一步
- 如果继续推进，下一条推荐指令是什么

---

## 交互要求

### 写文件要求

- 首次触发 skill 时，第一份真实产物必须是 `00_任务卡.md`
- 每进入一个阶段，只要该阶段声明了“输出”，就必须先在当前工作空间根目录创建或更新对应 `.md` 文件
- 聊天中的摘要必须基于刚刚写入的文件内容，而不是只在回复里临时组织文本
- 如果用户没有指定保存位置，默认就是当前工作空间根目录
- 如果当前目录已存在同名文件，应更新该文件，而不是改写到 skill 目录
- 绝对不要把任何产物写到 `references/`、`.skills/` 或 skill 包内部
- 如需引用 reference，只读取后再把结论写入当前工作空间根目录的产物文件

### 标准输出结构

每次执行指令时，按下面顺序输出：

1. `当前阶段`
2. `已读取参考`
3. `已生成文件`
4. `摘要`
5. `下一步建议`

### 聊天窗口篇幅控制

默认不要把完整 md 原样全刷出来。  
优先输出：

- 文件名
- 核心摘要
- 关键表格或关键结论的简版
- 下一步指令

只有当用户明确说“把全文贴出来”，才完整展示文档正文。

### 连续执行规则

如果用户说：

- “继续”
- “按默认流程往下走”
- “把前面几步都跑完”
- “先做到目录”
- “先做到角色映射”
- “先给我样章”

则可以连续执行多个阶段。  
但仍要在每个阶段：

- 先落成 md
- 再给阶段摘要
- 再进入下一步

---

## 何时提醒用户确认

以下情形必须主动提醒，而不是闷头写到底：

1. 准备把前 5 集目录扩成完整目录时
2. 准备从样章切换到批量分集时
3. 自检发现相似度风险为中或高时
4. 参考材料明显不足，却要直接整季开发时

---

## 模型限制

必须避免以下行为：

- 首次触发时不建立 `00_任务卡.md`
- 用户刚给材料，就直接整部剧写完
- 只做空泛分析，不落成具体 md
- 不读取 reference 就瞎写
- 把产物错误写进 `.skills/`、skill 包或 `references/`
- 以“宿主环境可能不支持”为理由跳过真实写文件
- 角色映射和目录完全照搬原作表层
- 用户没指定，却默认扩到 50-70 集
- 明知风险高，仍继续沿高识别桥段写作

---

## 成功标准

一个合格的剧本复刻技能，至少要做到：

1. 参考材料能被整理成清晰输入
2. 风格拆解结果可直接支撑方案制定
3. 方案、角色、目录、样章能层层衔接
4. 每一步都有实际 md 产物
5. 用户既能高效推进，也能随时接管调整
6. 复刻的是“有效机制”，不是“原作换名”
