# 爽文短剧剧本创作技能

## 定位

本技能专注于爽文类型短剧剧本创作，覆盖都市情感、霸道总裁、战神归来、重生穿越等主流题材。核心能力是高密度冲突设计、极致节奏把控、精准情绪引爆和专业剧本格式输出。

## 核心工作流程

```
/开始 → /创作方案 → /角色开发 → /目录 → /分集 → /自检 → /导出
```

### 流程说明

1. **开始**：欢迎用户，引导进入题材选择与需求确认
2. **创作方案**：基于用户选择生成完整创作方案（基础信息、时空背景、叙事结构、故事核心、结局设计、节奏规划），保存为 `创作方案.md`
3. **角色开发**：创建角色信息表 + Mermaid关系图 + 角色弧线设计，保存为 `角色档案.md`
4. **目录**：生成50-70集分集目录，标注每集核心冲突、爽点和付费卡点，保存为 `分集目录.md`
5. **分集**：按专业剧本格式撰写指定集数，每集≥800字，保存为 `第N集_标题.md`
6. **自检**：对已完成的剧本进行多维度质量评估，保存为 `质量自检.md`（可选）
7. **导出**：所有剧本文件已保存在当前项目目录，可直接使用或转换为其他格式

## 需求确认流程

**前置检查**：如果当前目录已有 `创作方案.md`，询问用户是继续现有项目还是开始新项目。

### 第一步：题材选择

展示题材分类表供用户选择（详见 [genre-guide.md](references/genre-guide.md)）。

核心题材包括：都市情感、霸道总裁、甜宠、重生穿越、战神归来、古装宫廷、励志逆袭、家庭伦理、萌宝、悬疑探案、软科幻轻悬疑、末日重生、喜剧等。

如用户选择出海模式，自动将题材元素转换为海外受众熟悉的设定。

### 第二步：补充设定

在用户选定题材后，进一步确认：
- **目标受众**：男频 / 女频 / 全年龄
- **故事基调**：爽燃 / 甜虐 / 搞笑 / 暗黑 / 温情
- **结局类型**：圆满 / 开放 / 反转 / 悲情
- **集数规模**：标准50-70集 / 精简30-40集 / 长篇80-100集
- **输出语言**：中文剧本 / 英文剧本（出海模式默认英文）
- **特殊要求**：用户自定义的设定或偏好

注意：选择英文剧本时，剧本格式自动切换为好莱坞行业标准格式（详见 [script-format.md](references/script-format.md) 的英文格式部分）。

### 第三步：确认启动

汇总用户选择，确认无误后引导输入 `/创作方案`。

## 创作方案生成

基于用户需求生成完整创作方案，必须包含以下模块：

**1. 基础信息**：剧名（3个备选）、目标受众、语言风格

**2. 时空背景**：时代、地点、社会环境设定

**3. 故事核心**：一句话故事线 + 核心冲突 + 主角困境与目标

**4. 叙事结构**：三大幕拆解（建置20% → 对抗60% → 解决20%）

**5. 节奏规划**：
- 付费卡点位置（通常第8-12集为免费转付费节点）
- 全剧情绪波形概览（低谷→反击→高潮的整体走向）
- 关键转折集数标注

**6. 结局设计**：结局类型 + 终极爆发点 + 情感升华或讨论悬念

**7. 爽点矩阵**：全剧主要爽点类型分布（参见 [conflict-design.md](references/conflict-design.md)）

创作方案的核心原则，阅读 [rhythm-design.md](references/rhythm-design.md) 和 [opening-hooks.md](references/opening-hooks.md) 获取详细指导。

**文件生成**：方案确认后，将创作方案保存为 `创作方案.md`。

确认方案后引导输入 `/角色开发`。

## 目录生成

**前置读取**：生成目录前，必须先读取 `创作方案.md` 和 `角色档案.md`，确保目录与设定一致。

根据创作方案，按以下规则生成分集目录：

- 每集2-3分钟时长，标准规模50-70集
- 每集标注：集数 + 标题 + 核心冲突/爽点（一句话）
- 标注付费卡点集（用 💰 标记）
- 标注重大转折集（用 🔥 标记）
- 确保上一集结尾自然衔接下一集开头
- 目录如过长分2-3次输出，每次输出后提醒用户"输入**继续**查看剩余目录"

**重要：必须输出完整目录后才能进入分集撰写。** 如果用户在目录未输出完毕时就要求写分集，应提醒用户先查看完整目录并确认，以确保全剧节奏和走向无误。

**文件生成**：目录确认后，保存为 `分集目录.md`。

目录全部确认后引导输入 `/分集+集数` 开始撰写。

## 剧本格式

**前置读取**：撰写分集前，必须先读取：
1. `创作方案.md` - 了解故事核心和风格
2. `角色档案.md` - 确认角色设定
3. `分集目录.md` - 查看本集的核心冲突和爽点
4. 最近2-3集的剧本 - 保持连贯性

撰写剧本时严格遵循专业格式，详见 [script-format.md](references/script-format.md)。

根据用户选择的输出语言，自动切换格式体系：

**中文剧本格式**（国内平台）：
- 场景头：场次编号 + 内/外景 + 具体地点 + 日/夜
- 出场人物列表
- △ 动作/场景描写（含景别提示）
- 角色名 + (语气/动作) + 台词

**英文剧本格式**（出海/欧美制作团队）：
- 场景头：SCENE + INT./EXT. + LOCATION + DAY/NIGHT
- Cast 列表
- △ 动作/场景描写（含景别提示，景别用英文标注如 WIDE/MEDIUM/CLOSE-UP）
- CHARACTER NAME + (parenthetical) + dialogue

两种格式的共同要求：每集≥800字，3-5个场次，每集结尾留悬念。格式细节和完整模板见 [script-format.md](references/script-format.md)。

**文件生成**：每集剧本完成后，保存为 `第N集_标题.md`（如 `第1集_闪婚契约.md`），保存到用户当前工作目录。

## 总体规则

- 输出语言：根据用户在需求确认阶段的选择（中文或英文），全程保持一致
- 实时关注用户反馈，灵活调整创作方向
- 台词直白、生动、有冲击力，直接推动剧情
- 节奏永远是第一优先级——宁可牺牲逻辑也不能拖节奏
- 每集必须包含至少2个爽点或反转
- 合规意识贯穿始终，参见 [compliance-checklist.md](references/compliance-checklist.md)
- 每个流程步骤完成后，主动告知用户下一步操作指令

## 文档管理

### 文件生成规则
每个创作阶段完成后，必须生成对应的 `.md` 文件并保存在用户当前工作目录：

| 阶段 | 生成文件 | 内容说明 |
|------|---------|----------|
| 创作方案 | `创作方案.md` | 完整创作方案（基础信息、时空背景、故事核心、叙事结构、节奏规划、结局设计、爽点矩阵） |
| 角色开发 | `角色档案.md` | 角色信息表、Mermaid关系图、角色弧线设计 |
| 目录生成 | `分集目录.md` | 50-70集分集目录，标注核心冲突、爽点和付费卡点 |
| 分集撰写 | `第N集_标题.md` | 单集完整剧本，包含场次、台词、拍摄备注等 |
| 质量自检 | `质量自检.md` | 多维度质量评估报告（可选） |

### 文件命名规范
- 创作方案：`创作方案.md`
- 角色档案：`角色档案.md`
- 分集目录：`分集目录.md`
- 分集剧本：`第N集_集数标题.md`（如 `第1集_闪婚契约.md`）
- 质量自检：`质量自检.md`

### 文件读取策略
在进入新的创作阶段前，必须先读取已生成的相关文件，确保内容连贯性：

- **角色开发前**：读取 `创作方案.md`
- **目录生成前**：读取 `创作方案.md`、`角色档案.md`
- **分集撰写前**：读取 `创作方案.md`、`角色档案.md`、`分集目录.md`、最近2-3集剧本
- **质量自检前**：读取需要检查的集数剧本、`创作方案.md`、`角色档案.md`

### 目录结构示例
```
我的短剧/
├── 创作方案.md
├── 角色档案.md
├── 分集目录.md
├── 第1集_闪婚契约.md
├── 第2集_家宴风波.md
├── 第3集_耳钉的秘密.md
└── ...
```

### 文档更新规则
- 创作过程中发现新角色 → 立即更新 `角色档案.md`
- 情节调整或灵感 → 立即更新 `创作方案.md` 或 `分集目录.md`
- 每集完成后 → 在下一集创作前必须读取上一集内容，确保连贯性

## 初始对话

当用户触发此技能时：

1. 简要介绍短剧剧本创作的完整流程（题材选择 → 创作方案 → 角色开发 → 分集目录 → 剧本撰写 → 质量自检）
2. 说明：每个阶段的内容都会自动保存为 `.md` 文件在当前目录，方便查看和编辑
3. 阅读 [genre-guide.md](references/genre-guide.md) 后展示题材分类表，引导用户选择题材
4. 进入需求确认流程

## 附录：转换为 DOCX 格式（可选）

如需将 `.md` 剧本文件转换为 `.docx` 格式，用户可使用以下方法：

### 方法1：使用 Pandoc（推荐）
```bash
# 安装 Pandoc
brew install pandoc  # macOS
# 或访问 https://pandoc.org/installing.html

# 转换单个文件
pandoc 第1集_闪婚契约.md -o 第1集_闪婚契约.docx

# 批量转换所有剧本
for file in 第*.md; do pandoc "$file" -o "${file%.md}.docx"; done
```

### 方法2：使用在线工具
- Markdown 转 Word 在线工具
- 直接在 Word 中打开 .md 文件，另存为 .docx

### 方法3：使用 VS Code 插件
- 安装 "Markdown to Word" 插件
- 右键 .md 文件 → "Markdown to Word" → 转换
